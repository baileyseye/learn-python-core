Python Core — это фундамент, а не финиш. После курса вы умеете читать и писать обычный Python-код, понимаете коллекции, исключения, ООП и основы веба. Дальше стоит выбрать прикладное направление и закрепить знания проектом.

## Ближайшие темы

<Steps>

1. **SQL и базы данных.** Начните с PostgreSQL или SQLite: `SELECT`, `JOIN`, `GROUP BY`, индексы, транзакции. Без SQL не обходится почти ни один бэкенд.
2. **Django или FastAPI.** Django даёт админку, ORM и готовую структуру. FastAPI — минимализм, async и автоматическую документацию. Выберите одно и сделайте проект.
3. **Тестирование.** pytest, фикстуры, параметризация, `pytest-cov`, mock. Умение писать тесты отличает рабочего разработчика от «человека, который смотрел курс».
4. **Git и командная работа.** Ветки, pull request, code review, конфликты, осмысленные коммиты.
5. **Инструменты.** `uv` или Poetry, Docker, логирование, линтеры (`ruff`), типы (`mypy`), CI на GitHub Actions.

</Steps>

## Что сделать проектом

Лучше всего знания закрепляет небольшой сервис, который вы сами придумали и довели до работающего состояния. Например:

- **REST API для заметок или задач** на FastAPI + SQLite/PostgreSQL.
- **Парсер и агрегатор данных** с сохранением в базу и отчётом.
- **Телеграм-бот**, который ходит во внешний API и хранит историю.
- **Мини-библиотека** с выдачей книг, пользователями и сроками возврата.
- **CLI-утилита**, которая автоматизирует вашу рутину.

Главное — не размер проекта, а завершённость: запуск, тесты, README и понятный сценарий использования.

## Полезные привычки

<Aside type="tip" title="Читайте чужой код">
  Открывайте исходники библиотек, которые используете. Начинайте с небольших модулей:
  как устроен `collections.Counter`, как работает `pathlib.Path`, как организован `dataclasses`.
</Aside>

- Пишите код руками, а не только читайте примеры.
- После каждой темы делайте маленькое упражнение.
- Возвращайтесь к старым урокам, если встретили незнакомую конструкцию.
- Заведите привычку объяснять код вслух или в заметках. Если не получается объяснить — вы ещё не поняли.
- Добавляйте тесты к каждой функции, которую будете менять позже.
